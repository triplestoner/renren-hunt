## 一、MVP目标

### 1.1 一句话目标

用最小产品验证：企业是否愿意把高价值岗位放到平台托管，SOHO猎头是否愿意接单推荐，平台是否能通过推荐归属存证、流程追踪和托管结算降低纠纷。

### 1.2 版本判断

1.0不是完整的链上猎头信用基础设施，也不是AI招聘平台。

1.0只验证一个闭环：

```
企业发布真实HC
→ 平台审核并托管规则
→ 猎头接单推荐候选人
→ 推荐归属存证
→ 企业反馈面试/录用结果
→ 保证期追踪
→ 佣金结算
→ 履约数据沉淀
```

### 1.3 MVP成功标准

| 指标 | 目标值 | 验证意义 |
|------|--------|----------|
| 签约企业数 | 5-10家 | 验证需求方愿意试用 |
| 入驻猎头数 | 30-50人 | 验证供给方愿意接单 |
| 有效岗位数 | 50-100个 | 验证平台有足够可接单HC |
| 有效推荐数 | 200+ | 验证猎头真实使用 |
| 面试转化数 | 20+ | 验证推荐质量 |
| 入职成单数 | 3-5单 | 验证交易闭环 |
| 推荐归属争议 | ≤2起 | 验证存证价值 |
| 企业7日反馈率 | ≥80% | 验证流程可控 |
| 猎头次月留存 | ≥40% | 验证供给侧价值 |

## 二、目标用户

### 2.1 优先用户

#### 用户A：出海/硬科技企业招聘负责人

| 维度 | 描述 |
|------|------|
| 典型画像 | AI、芯片、新能源、跨境电商、智能制造企业的招聘负责人或创始团队 |
| 核心痛点 | 高价值岗位难招，传统猎头贵且交付不稳定，多个猎头同时推荐时容易产生归属纠纷 |
| MVP诉求 | 快速获得候选人、看清推荐进度、降低猎头合作纠纷、按结果付费 |
| 关键顾虑 | 候选人质量、岗位保密、佣金规则、候选人重复推荐 |

#### 用户B：垂直领域SOHO猎头

| 维度 | 描述 |
|------|------|
| 典型画像 | 有3年以上猎头经验，深耕AI、芯片、新能源、出海等垂直行业 |
| 核心痛点 | 好岗位获取不稳定，回款慢，推荐归属难证明，候选人被截胡 |
| MVP诉求 | 获得真实高价值HC、明确佣金、推荐归属有记录、结算规则透明 |
| 关键顾虑 | 企业是否真实、平台是否拖款、同一候选人归属如何判定 |

### 2.2 暂不优先服务的用户

| 用户 | 暂缓原因 |
|------|----------|
| 普通候选人开放注册 | MVP阶段候选人主要由猎头推荐，避免冷启动获客过重 |
| 推荐人/行业专家 | 推荐人生态需要奖励和风控体系，放到2.0验证 |
| 小型猎头公司团队管理 | 先验证个人SOHO猎头，再做组织能力 |
| 广泛中小企业 | 客单价和服务噪音不确定，先聚焦高价值岗位 |

## 三、产品范围

### 3.1 MVP包含

| 模块 | 功能 | 目标 |
|------|------|------|
| 企业端 | 企业认证、岗位发布、岗位管理、候选人查看、面试反馈、录用确认 | 让企业能发布真实HC并管理推荐流程 |
| 猎头端 | 实名认证、领域标签、岗位大厅、接单、候选人推荐、进度查看 | 让猎头能找到岗位并提交候选人 |
| 推荐归属 | 推荐记录生成、候选人手机号/邮箱哈希去重、推荐时间戳、归属状态 | 降低飞单、撞单和归属争议 |
| 状态追踪 | 已推荐、企业已查看、约面、面试通过、offer、入职、保证期、结算 | 让双方看清流程 |
| 托管结算 | 佣金规则配置、结算节点、保证期倒计时、结算记录 | 建立回款信任 |
| 运营后台 | 企业审核、猎头审核、岗位审核、推荐审核、争议处理、数据看板 | 支撑人工运营交付 |

### 3.2 MVP不包含

| 暂不做 | 原因 |
|--------|------|
| 完整CCA候选人信用档案 | 数据源不足，隐私和合规成本高 |
| 完整TrustScore算法 | 冷启动无足够履约数据，先用认证和履约事实展示 |
| RRP积分/通证生态 | 容易引入监管和激励套利风险 |
| AI匹配98.7%目标 | 初期无训练数据，不承诺精度 |
| 社交图谱导入 | 微信/脉脉授权难度高，隐私风险高 |
| 跨平台TrustScore迁移 | 需要生态合作，非MVP核心 |
| 出海合规全包 | 先提供材料清单和合作伙伴入口，不承诺法律服务 |
| 区块链全流程上链 | 先做关键事件哈希存证，业务数据链下保存 |

## 四、核心业务规则

### 4.1 岗位规则

| 规则 | 说明 |
|------|------|
| 岗位类型 | MVP只开放高价值岗位，建议年薪30万以上 |
| 优先领域 | AI、芯片、新能源、跨境电商、智能制造、出海业务 |
| 岗位审核 | 平台审核企业资质、岗位真实性、薪资范围、佣金规则 |
| 保密岗位 | 可隐藏企业名称，但需展示行业、规模、地点、薪资、核心要求 |
| 佣金口径 | 按候选人税前年薪的一定比例计算，具体比例由企业与平台确认 |

### 4.2 猎头接单规则

| 规则 | 说明 |
|------|------|
| 入驻门槛 | 实名认证、手机号、微信、从业经历、擅长领域 |
| 接单权限 | 新猎头每日最多接3个岗位，完成有效推荐后逐步放开 |
| 推荐限制 | 同一岗位同一猎头最多推荐5名候选人 |
| 候选人授权 | 猎头提交前需确认已获得候选人求职意向和信息授权 |
| 违规处理 | 虚假推荐、无授权推荐、恶意占坑会被限制接单 |

### 4.3 推荐归属规则

推荐归属是1.0 MVP最核心的信任功能。

| 场景 | 判定规则 |
|------|----------|
| 首次推荐 | 以候选人手机号/邮箱哈希 + 岗位ID + 推荐时间戳生成推荐记录 |
| 重复推荐 | 同一岗位同一候选人，优先归属最早有效推荐者 |
| 无效推荐 | 候选人明确否认授权、联系方式错误、简历严重不实，归属失效 |
| 归属保护期 | 推荐后默认保护90天，可按岗位配置调整 |
| 争议处理 | 平台运营查看推荐记录、候选人确认、企业沟通记录后裁决 |

### 4.4 结算规则

| 规则 | 说明 |
|------|------|
| 企业付费 | MVP优先采用签约后预付/托管部分服务费，降低回款风险 |
| 结算节点 | 候选人入职并通过保证期后结算 |
| 保证期 | 默认90天，部分岗位可配置30/60/90天 |
| 分账对象 | MVP只向猎头结算，不设置候选人固定分账 |
| 候选人奖励 | 可作为运营补贴单独配置，不进入核心佣金分账模型 |
| 平台收入 | 平台从服务费中抽取约定比例，具体在商务合同中确定 |

## 五、核心流程

### 5.1 企业发布岗位

```
企业注册/登录
→ 提交企业认证
→ 创建岗位
→ 设置薪资、地点、要求、佣金规则、保证期
→ 平台审核
→ 岗位上架到猎头大厅
```

验收标准：
- 企业可以创建、编辑、下架岗位。
- 岗位未审核前不可被猎头接单。
- 保密岗位对猎头展示脱敏企业信息。

### 5.2 猎头接单推荐

```
猎头注册/登录
→ 完成实名认证和领域标签
→ 浏览岗位大厅
→ 查看岗位详情
→ 接单
→ 提交候选人信息和推荐理由
→ 系统生成推荐归属记录
→ 企业查看候选人
```

验收标准：
- 猎头只能推荐已接单岗位。
- 重复候选人会触发提醒。
- 推荐成功后生成不可编辑的推荐时间戳记录。

### 5.3 企业反馈与状态追踪

```
企业查看候选人
→ 标记是否进入沟通
→ 标记是否约面
→ 填写面试反馈
→ 标记offer/拒绝
→ 标记入职
→ 进入保证期
```

验收标准：
- 每个候选人都有唯一状态。
- 企业超过7天未反馈时，系统提醒运营介入。
- 猎头可查看状态变化，但不能修改企业反馈。

### 5.4 保证期与结算

```
企业确认入职
→ 系统生成保证期倒计时
→ 保证期内记录离职/异常
→ 保证期结束
→ 运营确认结算条件
→ 生成结算单
→ 完成打款并记录
```

验收标准：
- 每笔成单有明确保证期结束时间。
- 每笔结算可追溯到岗位、候选人、猎头和合同规则。
- 异常结算必须有运营备注。

## 七、数据设计

### 7.1 核心对象

| 对象 | 关键字段 |
|------|----------|
| 企业 | 企业ID、名称、认证状态、联系人、行业、规模 |
| 猎头 | 猎头ID、姓名、认证状态、领域标签、接单权限、履约记录 |
| 岗位 | 岗位ID、企业ID、标题、薪资、城市、领域、佣金规则、保证期、状态 |
| 候选人 | 候选人ID、姓名、手机号哈希、邮箱哈希、简历附件、授权状态 |
| 推荐 | 推荐ID、岗位ID、猎头ID、候选人ID、推荐理由、时间戳、归属状态 |
| 流程状态 | 推荐ID、当前阶段、状态更新时间、企业反馈、运营备注 |
| 结算单 | 结算ID、推荐ID、佣金金额、平台服务费、猎头应得、结算状态 |
| 存证记录 | 事件ID、事件类型、业务对象ID、哈希值、时间戳 |

### 7.2 存证范围

MVP只对关键事件做哈希存证，不把个人敏感信息上链。

| 事件 | 是否存证 | 说明 |
|------|----------|------|
| 岗位审核通过 | 是 | 证明岗位规则版本 |
| 猎头接单 | 是 | 证明接单时间 |
| 候选人推荐 | 是 | 证明推荐归属 |
| 企业查看候选人 | 是 | 证明企业已接收推荐 |
| 入职确认 | 是 | 证明成单节点 |
| 结算完成 | 是 | 证明履约结果 |
| 简历原文 | 否 | 仅链下加密保存 |
| 薪资细节 | 否 | 仅保存业务必要字段 |
| 面试评价全文 | 否 | 链下保存，可生成摘要哈希 |

## 八、非功能需求

| 类型 | 要求 |
|------|------|
| 隐私 | 手机号、邮箱、身份证等敏感信息加密存储；推荐去重使用哈希 |
| 权限 | 企业只能看自己岗位下的候选人；猎头只能看自己推荐的进度 |
| 审计 | 关键状态变更必须记录操作者、时间、前后状态 |
| 可用性 | 核心流程移动端可用，猎头端优先适配手机 |
| 安全 | 简历附件需鉴权下载，链接不可公开访问 |
| 合规 | 用户需确认候选人授权；平台保留授权记录和操作日志 |

## 九、运营策略

### 9.1 冷启动打法

| 阶段 | 动作 |
|------|------|
| 第1-2周 | 定向签约5家出海/硬科技企业，收集真实高薪HC |
| 第2-4周 | 邀请30-50名垂直SOHO猎头入驻，人工审核领域能力 |
| 第4-8周 | 平台运营人工撮合重点岗位，追踪每个推荐状态 |
| 第8-10周 | 复盘首批成单、争议、反馈率和猎头留存 |

### 9.2 首批领域建议

优先选择高价值且猎头专业度明显的领域：
- AI算法/大模型
- 芯片设计/半导体设备
- 新能源三电/储能
- 跨境电商中高层
- 出海业务负责人/海外市场负责人

### 9.3 人工运营原则

MVP阶段不追求全自动。平台运营要主动介入：
- 帮企业规范JD和佣金规则。
- 帮猎头理解岗位真实需求。
- 对7天无反馈的企业做人工催办。
- 对重复候选人和归属争议做人工裁决。
- 对首批成单做案例沉淀。

## 十、风险与应对

| 风险 | 概率 | 影响 | 应对 |
|------|------|------|------|
| 企业岗位不真实或反馈慢 | 中 | 高 | 岗位审核、7日反馈提醒、运营介入、低反馈企业降权 |
| 猎头恶意占坑 | 中 | 高 | 推荐数量限制、候选人授权确认、无效推荐扣权限 |
| 候选人重复推荐争议 | 高 | 高 | 手机/邮箱哈希去重、首推时间戳、保护期规则 |
| 企业绕过平台私下成交 | 中 | 高 | 合同约定、推荐存证、候选人保护期、关键节点追踪 |
| 结算回款慢 | 中 | 高 | 预付/托管部分费用，结算规则前置确认 |
| 出海合规承诺过度 | 中 | 高 | MVP只做撮合和流程管理，法律服务由合作方提供 |
| AI能力无法兑现 | 低 | 中 | MVP不承诺AI精度，只做人工运营和规则化筛选 |

## 十一、里程碑

### 11.1 8-10周交付计划

| 周期 | 目标 | 交付物 | 验证 |
|------|------|--------|------|
| 第1-2周 | 完成业务规则和原型 | 企业端、猎头端、后台原型；佣金和归属规则 | 5家企业、10名猎头访谈确认 |
| 第3-4周 | 完成核心建模和审核流程 | 企业/猎头/岗位/推荐/状态模型 | 能创建岗位并完成审核 |
| 第5-6周 | 完成推荐归属和状态追踪 | 接单、推荐、去重、状态流转 | 能跑通推荐到面试 |
| 第7-8周 | 完成结算与运营后台 | 保证期、结算单、争议处理 | 能跑通入职到待结算 |
| 第9-10周 | 小范围试运营 | 真实企业和猎头灰度使用 | 达成首批有效推荐和面试 |

### 11.2 发布门槛

上线前必须满足：
- 企业、猎头、岗位审核流程可用。
- 推荐归属记录不可被普通用户修改。
- 候选人重复推荐能被识别。
- 企业反馈状态可追踪。
- 运营后台能处理争议和结算异常。
- 敏感信息加密或脱敏展示。

## 十三、关键结论

人人猎1.0 MVP的核心不是证明“区块链招聘平台”这个大概念，而是证明一个更具体的交易价值：

企业愿意为真实高价值岗位托管规则，猎头愿意在平台接单推荐，平台能清楚记录推荐归属并推动结算。

只要这个闭环成立，TrustScore、AI匹配、候选人信用档案、推荐人生态和出海服务都可以自然长出来。反过来，如果这个闭环不成立，做再多上层能力也无法形成真实交易。

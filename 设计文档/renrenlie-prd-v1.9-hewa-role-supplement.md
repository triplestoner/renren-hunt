# 人人猎 PRD v1.9（禾蛙角色体系补充版）

版本：v1.9  
日期：2026年5月28日  
基线文档：`renrenlie-prd-v1.8.md`  
本版主题：参考禾蛙的角色分层、交易触点和推荐人端首页，补齐人人猎 PRD1.8 中的角色体系与 MVP 边界。

---

## 0. 本版修订目标

PRD1.8 已经覆盖候选人、SOHO 猎头、推荐人、企业 HR、小型猎头公司五类用户，但这些更偏用户画像，尚未充分拆开真实交易中的职责、权限和页面触点。参考禾蛙后，本版将用户体系从“五类用户”升级为“交易角色层”：

1. 明确发单方、接单方、候选人、平台运营、邀请增长、AI 助手之间的边界。
2. 补齐各角色从入驻、认证、发单、接单、推荐、反馈、结算到复购的核心触点。
3. 将禾蛙可复刻的首页结构沉淀为人人猎推荐人端和接单端的信息架构。
4. 收敛 MVP：优先验证“企业真实岗位 -> 平台审核/托管 -> 接单推荐 -> 推荐归属 -> 反馈追踪 -> 结算”的闭环。

---

## 1. 禾蛙角色拆解与人人猎映射

禾蛙的产品不是简单的“企业 + 猎头 + 候选人”三方结构，而是围绕岗位交付把角色拆成多层。人人猎应复刻其中的交易分工，而不是直接照搬页面。

| 禾蛙角色 | 人人猎对应角色 | 核心任务 | 核心触点 | MVP处理 |
|---|---|---|---|---|
| 接单顾问 | SOHO猎头 / 推荐人 / 兼职顾问 | 找职位、接单、推荐人才、跟进反馈、赚取佣金 | 首页推荐、搜索、专场职位、开始做单、我的人才、订单、奖励中心 | P0 |
| 发单猎企 / 企业HR | 企业HR / 招聘负责人 | 发布职位、审核人选、安排面试、确认 offer、支付服务费 | 发布职位、职位管理、候选人列表、反馈节点、合同与付款 | P0 |
| 猎企管理员 | 小型猎头公司 / 团队管理员 | 管理团队、分配职位、查看团队绩效、处理结算 | 团队工作台、成员权限、职位池、团队榜单、结算明细 | P1 |
| 候选人 | 被推荐人才 / 自主求职者 | 授权简历、确认推荐、参加面试、入职履约 | 授权确认、职位详情、面试进度、隐私设置、入职确认 | P0 |
| 邀请人 | 老用户 / 渠道推荐人 | 邀请新人、激活新用户、获得推荐奖励 | 邀请链接、奖励中心、邀请记录、到账状态 | P1 |
| 被邀请新用户 | 新注册接单方 / 新企业用户 | 完成注册认证、首单或首次发单 | 新人福利、实名认证、首推/首发任务、奖励发放 | P1 |
| 平台客服 / 运营 | 平台运营 / 项目PM / 审核 / 结算 | 审核职位、协调反馈、处理争议、管理奖励、沉淀规则 | 运营后台、审核队列、争议工单、结算中心、消息通知 | P0 |
| AI助手 | AI匹配 / JD解析 / 推荐助手 | 辅助找职位、解析JD、推荐候选人、生成沟通建议 | 搜索框、职位详情、推荐建议、消息侧栏、问答入口 | P1 |

结论：人人猎 PRD1.8 中的“推荐人”需要从单一增长角色升级为可接单、可推荐、可被激励的轻量接单方；“企业 HR”需要与“发单猎企/团队管理员”区分；“平台运营”必须作为一等角色进入 MVP，因为托管、归属和结算都依赖平台治理。

## 2. 人人猎 v1.9 角色体系

### 2.1 候选人：被推荐人才与授权主体

候选人不是平台交易中的被动数据对象，而是推荐归属和隐私授权的关键主体。

| 项目 | 定义 |
|---|---|
| 核心目标 | 控制简历授权，减少被滥投，获得更可信的岗位机会 |
| 关键动作 | 创建或授权简历、确认被推荐、查看职位进度、确认面试和入职 |
| 关键数据 | 手机号/邮箱哈希、简历版本、授权记录、岗位ID、推荐时间戳、面试反馈 |
| 关键风险 | 未授权推荐、重复推荐、简历泄露、虚假面试反馈 |
| 产品策略 | MVP 先做授权和进度可见，复杂 CCA 和完整链上档案后置 |

核心触点：

- 注册/授权：手机号或邮箱验证、简历上传、隐私授权。
- 推荐确认：候选人收到“某顾问正在推荐你至某岗位”的确认通知。
- 进度查看：已推荐、企业已查看、初筛、面试、offer、入职、保证期。
- 争议确认：当存在重复推荐或授权争议时，候选人可确认真实接触方。

### 2.2 接单方：SOHO猎头、推荐人、兼职顾问

接单方是人人猎早期最重要的供给侧角色，应参考禾蛙的“接单顾问”设计成高频工作台。

| 项目 | 定义 |
|---|---|
| 核心目标 | 快速找到适合自己资源圈层的岗位，低摩擦推荐候选人并获得可预期收益 |
| 关键动作 | 搜索职位、接单、查看岗位佣金、推荐候选人、跟进反馈、查看收益 |
| 关键数据 | 擅长行业、历史推荐、推荐通过率、面试通过率、offer金额、结算状态 |
| 关键风险 | 乱接单、低质量推荐、重复推荐、刷奖励 |
| 产品策略 | MVP 优先服务“接单 -> 推荐 -> 状态追踪 -> 结算”闭环 |

核心触点：

- 首页工作台：本周推荐数、初筛通过数、面试通过数、待跟进任务。
- 搜索与筛选：按职位、公司、城市、行业、佣金、反馈速度筛选。
- 专场职位：新人专区、高反馈专区、高佣金专区、急招专区。
- 职位详情：佣金、保证期、候选人要求、推荐限制、企业反馈 SLA。
- 推荐动作：上传简历、绑定候选人授权、生成推荐归属记录。
- 订单/收益：推荐进度、佣金预估、保证期倒计时、到账记录。
- 榜单/激励：offer金额榜、推荐通过榜、新人首单榜。

### 2.3 发单方：企业HR、招聘负责人、发单猎企

发单方是平台需求侧，PRD1.8 中“企业 HR”需要扩展为“职位发布者 + 反馈责任方 + 付款责任方”。

| 项目 | 定义 |
|---|---|
| 核心目标 | 用更低协作成本获得可信候选人，并减少多猎头协作中的重复推荐和结算争议 |
| 关键动作 | 发布职位、设置佣金、审核推荐、反馈面试、确认 offer、支付服务费 |
| 关键数据 | 职位预算、候选人状态、反馈时效、成单率、付款和保证期记录 |
| 关键风险 | 虚假岗位、反馈拖延、绕开平台、拒付佣金 |
| 产品策略 | MVP 必须绑定职位审核、反馈时限、推荐归属和支付凭证 |

核心触点：

- 发布职位：岗位信息、薪资范围、招聘人数、城市、佣金比例、保证期。
- 职位审核：平台审核通过后进入可接单池。
- 推荐列表：按推荐时间、匹配度、接单方信用、候选人授权状态查看。
- 反馈节点：不合适、进入初筛、面试、offer、入职。
- 合同/付款：服务协议、付款节点、保证期规则、发票与结算凭证。

### 2.4 猎企团队管理员：小型猎企与工作室负责人

团队管理员不是 MVP 的第一优先级，但 PRD1.8 中的小型猎头公司需要保留清晰演进路径。

| 项目 | 定义 |
|---|---|
| 核心目标 | 把多个顾问的职位、候选人、绩效和结算集中管理 |
| 关键动作 | 邀请成员、分配职位、查看团队漏斗、管理结算权限 |
| 关键数据 | 成员推荐数、初筛率、面试率、offer金额、团队佣金 |
| MVP处理 | P1，不影响个人接单闭环时后置 |

核心触点：

- 团队成员：添加顾问、设置角色、冻结成员。
- 团队职位池：统一接单后分配给成员。
- 团队数据：本周推荐、面试、offer、佣金。
- 结算分配：团队账户、成员分账、争议处理。

### 2.5 平台运营：审核、项目PM、客服、结算、风控

禾蛙的页面中“客服、反馈、消息、奖励、活动规则”说明平台运营是交易闭环的一部分。人人猎要把平台运营作为产品角色，而不是后台附属功能。

| 项目 | 定义 |
|---|---|
| 核心目标 | 保障岗位真实、推荐归属清晰、反馈及时、结算可信 |
| 关键动作 | 审核职位、处理重复推荐、催反馈、处理争议、发放奖励 |
| 关键数据 | 审核时长、反馈 SLA、争议率、结算周期、奖励发放状态 |
| 关键风险 | 运营不介入导致平台信任坍塌 |
| 产品策略 | MVP 必须保留最小运营后台 |

核心触点：

- 职位审核队列：审核企业资质、岗位真实性、佣金规则。
- 推荐归属队列：查看手机号/邮箱哈希、岗位ID、时间戳和授权记录。
- 反馈催办：对超时企业发送提醒，必要时运营介入。
- 争议工单：重复推荐、候选人授权、面试归因、佣金结算争议。
- 奖励中心：新人奖励、邀请奖励、活动奖励的审核与发放。

### 2.6 邀请增长角色：邀请人与被邀请新用户

禾蛙的新人福利和推荐奖励可以复刻，但不应成为 MVP 主线。人人猎应把它定位为“供给侧冷启动工具”，在第一交易闭环跑通后开启。

| 角色 | 核心目标 | 核心触点 | 进入时机 |
|---|---|---|---|
| 邀请人 | 通过邀请新接单方或企业获得奖励 | 邀请链接、邀请记录、奖励中心、到账状态 | P1 |
| 被邀请新接单方 | 完成认证并完成首推 | 新人任务、首推奖励、推荐教学、职位专区 | P1 |
| 被邀请企业 | 完成认证并发布首个真实职位 | 企业认证、首发职位奖励、平台审核、托管规则 | P1 |

推荐奖励需要绑定真实行为，不按注册发放。建议奖励节点为：

1. 完成实名认证。
2. 完成首个有效推荐或首个有效职位发布。
3. 候选人进入面试或职位收到有效推荐。
4. 成单并过保证期后发放大额奖励。

### 2.7 AI助手：系统能力，不作为独立交易主体

禾蛙的 Domi AI/问小蛙说明 AI 可以成为高频辅助入口。人人猎应把 AI 定位为“辅助推荐效率的工具”，不要在 MVP 中承诺高精度自动匹配。

MVP 后可做的 AI 触点：

- JD 解析：提取行业、职级、薪资、硬性条件、加分项。
- 接单建议：判断该职位是否适合某接单方历史资源。
- 候选人推荐摘要：生成推荐理由，辅助企业快速判断。
- 沟通建议：生成候选人邀约话术和企业反馈追问。
- 问答入口：解释佣金、保证期、推荐归属和平台规则。

## 3. 各角色核心触点总表

### 3.1 入驻与认证触点

| 角色 | 入口 | 必填信息 | 审核方 | 通过后状态 |
|---|---|---|---|---|
| 接单方 | 注册 / 邀请链接 / 新人专区 | 手机号、身份、擅长行业、历史经验 | 平台运营 | 可浏览职位，可申请接单 |
| 发单方 | 企业入驻 / 发布职位 | 企业资质、联系人、岗位信息、付款规则 | 平台运营 | 可发布职位，待审核后开放接单 |
| 候选人 | 推荐授权 / 自主注册 | 联系方式、简历、授权范围 | 系统 + 运营抽检 | 可被推荐，可查看进度 |
| 团队管理员 | 猎企入驻 | 公司资质、管理员身份、成员信息 | 平台运营 | 可创建团队和分配职位 |

### 3.2 发单与接单触点

| 流程 | 发单方触点 | 接单方触点 | 平台触点 | 候选人触点 |
|---|---|---|---|---|
| 发布职位 | 发布表单、佣金设置、保证期设置 | 暂无 | 审核职位真实性 | 暂无 |
| 职位开放 | 职位管理、推荐接收规则 | 首页推荐、搜索、专场职位 | 职位分发、风控标签 | 暂无 |
| 接单 | 查看接单方数量 | 申请接单、收藏、开始做单 | 接单限制、黑名单校验 | 暂无 |
| 推荐候选人 | 接收推荐列表 | 上传简历、填写推荐理由 | 生成归属记录 | 授权确认 |
| 反馈跟进 | 初筛/面试/offer反馈 | 查看状态、补充材料 | 超时提醒、争议处理 | 查看进度 |
| 入职结算 | 确认入职、付款 | 查看佣金、保证期 | 托管、结算、发票 | 入职确认 |

### 3.3 增长与激励触点

| 激励类型 | 目标角色 | 触发条件 | 风控要求 |
|---|---|---|---|
| 新人首推奖励 | 新接单方 | 首次有效推荐进入企业查看或初筛 | 候选人授权 + 非重复推荐 |
| 首次推荐奖 | 邀请人 | 被邀请接单方完成首个有效推荐 | 排除同设备/同手机号异常 |
| 首发职位奖 | 新发单方 | 企业完成认证并发布真实职位 | 运营审核 + 职位开放 |
| 成单奖励 | 接单方 / 邀请人 | 候选人入职并通过保证期 | 付款完成 + 争议期结束 |

## 4. 推荐人端 / 接单方首页信息架构

参考禾蛙登录后首页，人人猎推荐人端应从“解释产品”切换为“直接做单”的工作台。

### 4.1 顶部导航

建议导航：

- 首页
- 职位
- 我的候选人
- 我的推荐
- 订单 / 结算
- 奖励中心
- 学院
- AI助手
- 个人中心

原则：推荐人端不应把“区块链、CCA、TrustScore”放在主导航里。信任能力应体现在接单限制、推荐归属、结算状态和争议处理里。

### 4.2 搜索区

搜索对象：

- 职位
- 公司
- 城市
- 行业
- 佣金区间

热搜建议：

- 高反馈职位
- 本周急招
- 高佣金
- 远程 / 出海
- AI / 芯片 / 新能源

### 4.3 本周数据

首页首屏显示接单方最关心的可行动数据：

| 指标 | 说明 | 点击后去向 |
|---|---|---|
| 本周推荐 | 本周提交的有效候选人数 | 我的推荐 |
| 初筛通过 | 企业确认进入初筛的人选数 | 待跟进列表 |
| 面试通过 | 进入面试或下一轮的人选数 | 面试进度 |
| 待反馈 | 超过 SLA 未反馈的人选数 | 催反馈任务 |
| 预计佣金 | 已进入关键节点的佣金预估 | 结算中心 |

主按钮：

- 开始做单：进入职位推荐流。
- 继续跟进：进入待处理任务。

### 4.4 专场职位

禾蛙的“专场职位”值得复刻，因为它能降低接单方找单成本。人人猎建议设置：

| 专场 | 目标 | 排序规则 |
|---|---|---|
| 新人不迷路 | 帮助新接单方完成首推 | 反馈快、要求清晰、佣金中等 |
| 高反馈专区 | 提升接单方信任感 | 企业 48 小时反馈率高 |
| 高佣金专区 | 吸引成熟猎头 | 佣金金额高、职位难度高 |
| 急招专区 | 提高交付速度 | 企业急招、反馈 SLA 短 |
| 出海 / 垂直岗位 | 承接 PRD1.8 战略方向 | 出海标签、行业专业度要求 |

### 4.5 职位流

职位流分为两类即可，避免 MVP 复杂化：

1. 为你推荐：基于接单方擅长行业、历史推荐、城市和职位偏好。
2. 本周上新：按发布时间和平台优先级展示。

职位卡片必须展示：

- 职位名称、公司匿名/实名状态、城市、薪资。
- 佣金或服务费区间。
- 企业反馈速度。
- 推荐人数/剩余推荐名额。
- 保证期和结算规则。
- 接单按钮。

### 4.6 榜单与侧边服务

禾蛙的榜单可以提升活跃，但不应影响 MVP 主路径。建议 P1 上线：

- offer 金额榜。
- 推荐通过率榜。
- 新人首单榜。
- 高反馈企业榜。

侧边服务建议：

- 消息。
- 客服。
- 反馈。
- 规则问答 / AI助手。

## 5. 发单方工作台补充

PRD1.8 对企业 HR 的描述偏少，本版补充发单方工作台。

### 5.1 首页核心模块

| 模块 | 目的 | 必要性 |
|---|---|---|
| 待处理候选人 | 提醒 HR 快速反馈 | P0 |
| 招聘职位 | 管理开放、暂停、关闭职位 | P0 |
| 本周数据 | 查看收到推荐、初筛、面试、offer | P0 |
| 付款与合同 | 查看托管、付款、保证期 | P0 |
| 推荐质量 | 查看接单方质量和重复推荐情况 | P1 |

### 5.2 反馈 SLA

为了让接单方愿意持续供给，发单方必须被明确约束反馈时限：

- 候选人提交后 48 小时内反馈是否进入初筛。
- 面试后 3 个工作日内更新结果。
- offer 后必须确认入职日期、薪资范围和保证期起始日。
- 超时反馈会影响企业信用标签和职位排序。

### 5.3 发单方信用标签

在 P1 阶段，可增加企业侧信用标签：

- 反馈快。
- 付款准。
- 成单高。
- 要求清晰。
- 争议低。

这些标签直接影响职位在接单方首页的排序。

## 6. 平台运营后台补充

MVP 中必须保留最小运营后台，否则推荐归属、托管和结算无法被验证。

### 6.1 P0后台能力

| 能力 | 说明 |
|---|---|
| 职位审核 | 审核企业资质、岗位真实性、佣金和保证期 |
| 用户审核 | 审核接单方身份、企业身份、团队管理员身份 |
| 推荐归属 | 查看候选人哈希、岗位ID、推荐时间戳和授权状态 |
| 状态管理 | 必要时由运营修正错误状态，并保留日志 |
| 反馈催办 | 对超过 SLA 的企业发提醒，生成待办 |
| 争议工单 | 处理重复推荐、绕开平台、拒付佣金、候选人授权争议 |
| 结算审核 | 确认付款、保证期、佣金发放和奖励发放 |

### 6.2 不进入 MVP 的后台能力

- 完整 TrustScore 模型配置台。
- 全流程链上合约自动化。
- 多团队复杂分账。
- 开放 API 管理台。
- RRP 积分生态运营台。
- 跨境合规管理台。

## 7. MVP边界调整

PRD1.8 的长期愿景包括区块链信用、AI匹配、出海招聘、垂直领域、中小企业、RRP 生态等。参考禾蛙后，MVP 应聚焦交易闭环。

### 7.1 P0：必须进入 MVP

| 模块 | 原因 |
|---|---|
| 企业发布职位与平台审核 | 没有真实职位就没有交易 |
| 接单方浏览、搜索、接单 | 供给侧高频入口 |
| 候选人推荐与授权确认 | 推荐归属和隐私保护的基础 |
| 推荐归属存证 | 人人猎区别于传统撮合平台的核心 |
| 企业反馈流 | 决定接单方是否持续供给 |
| 状态追踪 | 支撑候选人、接单方、发单方协同 |
| 保证期和结算 | 验证平台商业闭环 |
| 最小运营后台 | 支撑审核、争议、结算和托管 |

### 7.2 P1：首个闭环跑通后进入

| 模块 | 进入条件 |
|---|---|
| 新人福利 / 邀请奖励 | 已有可承接新人流量的职位池 |
| 专场职位增强 | 职位数量足够分类 |
| 榜单 | 有稳定行为数据 |
| 团队管理员 | 出现小型猎企批量入驻需求 |
| AI助手 | 已积累足够岗位和推荐数据 |
| 企业信用标签 | 有足够反馈、付款和争议样本 |

### 7.3 P2：继续后置

| 模块 | 后置原因 |
|---|---|
| 完整 CCA | 需要候选人规模和授权习惯支持 |
| 完整 TrustScore | 冷启动阶段数据不足 |
| RRP 生态 | 会分散交易闭环验证 |
| 98.7% AI匹配精度 | 指标定义和数据来源尚需验证 |
| 全流程上链 | 成本和复杂度高，先做关键事件哈希 |
| 出海合规全包 | 合规复杂，不适合作为第一 MVP 主线 |

## 8. 关键规则补充

### 8.1 推荐归属规则

MVP 推荐归属采用：

```
候选人联系方式哈希 + 岗位ID + 推荐时间戳 + 候选人授权状态
```

判定规则：

1. 同一岗位下，候选人授权有效且时间最早的推荐方获得首推归属。
2. 候选人未授权的推荐不进入有效归属。
3. 企业已在平台外接触过候选人时，必须上传证据，由平台运营判定。
4. 归属争议期间，相关候选人状态冻结，避免重复推进。
5. 关键事件只存哈希和日志，简历原文、薪资、面试评价等敏感信息链下保存。

### 8.2 反馈规则

| 节点 | 发单方动作 | 超时处理 |
|---|---|---|
| 推荐提交 | 48小时内反馈是否进入初筛 | 系统提醒，影响职位排序 |
| 初筛通过 | 更新面试安排或拒绝理由 | 接单方可申请运营催办 |
| 面试结束 | 3个工作日内更新结果 | 生成运营待办 |
| offer | 确认薪资、入职日、保证期 | 影响结算启动 |
| 保证期结束 | 确认是否通过保证期 | 进入佣金结算 |

### 8.3 奖励规则

奖励必须服务真实交易，不服务单纯拉新。

- 注册奖励不直接发放现金，只给任务资格或曝光权益。
- 首推奖励以“有效推荐”作为触发条件。
- 邀请奖励以被邀请人完成有效行为作为触发条件。
- 成单奖励必须在付款完成且保证期结束后发放。
- 异常账号、重复设备、虚假候选人、刷单行为进入风控队列。

## 10. v1.9 成功指标

相比 PRD1.8 的宏观指标，本版补充更适合 MVP 的交易指标。

| 指标 | 目标 | 说明 |
|---|---|---|
| 真实开放职位数 | 30-50个 | 有平台审核和明确佣金 |
| 认证接单方数 | 100-200人 | SOHO猎头、推荐人、兼职顾问 |
| 职位接单率 | >=60% | 开放职位被至少一名接单方接单 |
| 有效推荐率 | >=35% | 推荐候选人被企业查看或进入初筛 |
| 48小时反馈率 | >=70% | 发单方按时反馈 |
| 推荐归属争议率 | <=5% | 初期允许人工处理 |
| 入职成单数 | 5-10单 | 验证完整闭环即可 |
| 结算完成率 | >=90% | 到期应结算订单正常结算 |

## 11. 本版结论

禾蛙最值得人人猎复刻的不是活动页样式，而是围绕接单顾问形成的交易角色设计：

1. 把接单方首页做成工作台，而不是宣传页。
2. 把发单方从“企业HR画像”升级为“反馈和付款责任方”。
3. 把平台运营放进 MVP，因为信任不是自动生成的，需要审核、催办、争议和结算治理。
4. 把邀请奖励放在交易闭环之后，避免冷启动阶段被拉新任务带偏。
5. 把 AI 助手作为效率工具后置，不把高精度匹配当成 MVP 成功前提。

因此，人人猎 v1.9 的产品主线应调整为：

```
企业真实发单 -> 平台审核托管 -> 接单方接单推荐 -> 候选人授权确认 -> 企业反馈推进 -> 推荐归属沉淀 -> 保证期追踪 -> 佣金结算
```

这条主线跑通后，再叠加新人福利、榜单、团队管理员、AI助手、出海专区和完整 TrustScore。

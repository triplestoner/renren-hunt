## 一、产品愿景与战略定位

### 1.1 产品愿景

> **"让人才流动真正实现数字化、资产化与无缝化——通过技术的确定性，解决商业环境中的不信任，让信任在链上自由流转"**

人人猎不是又一个招聘平台，而是中高端人才招聘的**信任协议（Trust Protocol）**。

信任协议的核心逻辑：**将静态的社交关系转化为动态的人才资产，将不可追溯的交易变为链上可验证的信用流，将平台与猎头的利益博弈变为智能合约自动分账**。

每一个候选人的职业信用、每一段熟人的真实背书、每一笔智能托管的资金，都以加密签名形式上链，形成**可携带、可验证、不可篡改的动态人才资产**，在推荐网络中自由流转，持续升值。

### 1.2 战略定位

| 维度 | 描述 |
|------|------|
| **产品类型** | C2C2B 熟人社交推荐 × 去中心化招聘 × 信任协议 |
| **目标用户** | 候选人（核心资产所有者）、推荐官（推荐人）、企业 HR（需求方） |
| **核心价值主张** | 信任数字化流转 × 智能合约分账 × AI 精准匹配 × 零沉没成本 × 链上信用资产 |
| **对标参考** | LinkedIn（职业档案）+ Wanted（推荐体验）+ 区块链信用（资产逻辑）+ 传统猎头（商业模式） |
| **差异化壁垒** | 独家三维数据资产 + 沉睡高端隐私人才池 + 不可迁移的网状信用网络 |

### 1.3 传统模式之困：信任的结构性缺陷 🆕

**传统猎头招聘的六大结构性缺陷**：

| 缺陷维度 | 具体问题 | 后果 |
|---------|---------|------|
| **组织模式** | 单向树状扩散，信息由上至下流转 | 层级摩擦高，coldcall 效率随层级递减 |
| **技术漏洞** | 简历可私转/飞单，不可追溯 | 猎企利益受损，推荐者无效劳动 |
| **数据孤岛** | 候选人资源沉淀在猎头私域，无法共享形成规模化 | 候选人"需求方库内重合"导致推荐者无效劳动 |
| **隐私安全** | 候选人被动曝光，高端人才抗拒陌生联系 | 最优质的人才最难触达 |
| **利益分配** | 平台/老板吃大头，推荐者付出与收获不匹配 | 推荐者动力不足 |
| **企业成本** | 年薪 20-30%，高额预付沉没成本 | 企业承担巨大风险 |

**人人猎的降维打击**：

| 对比维度 | 传统猎头机构 | 人人猎 |
|---------|------------|------|
| 组织架构 | 单向树状扩散，高摩擦 | 网状裂变（C2C2B），指数级扩散 |
| 数据确权防作弊 | 极易泄露，飞单频发，不可追溯 | 区块链数字水印，全链路可追溯 |
| 隐私保护 | 被动曝光，高端人才抗拒 | DID 简历主权，候选人主动授权解锁 |
| 交付周期 | 2-3 个月，纯人工盲搜 | AI 引擎秒级筛选，熟人背书极速触达 |
| 利益分配 | 平台/老板吃大头，推荐者付出与收获不匹配 | 智能合约自动分账，两端获利最大化 |
| 企业成本 | 年薪 20-30%，高额预付沉没成本 | 降至月薪比例，无沉没成本 |

### 1.4 核心创新理念：信任协议驱动 🆕

人人猎的底层逻辑是 **"信任协议驱动"**：

```
B端圈层定向发榜（资金托管）
        ↓
  基于认证的智能派/抢单（80% 智能 + 20% 抢单）
        ↓
  私域触达与熟人背书（单向阀门，候选人授权解锁）
        ↓
  候选人单次授权与前置背调
        ↓
  履约与 HR 强制评价
        ↓
  信用回流与赏金分润（TrustScore 升级）

  候选人：信任数字化流转，职业信用持续升值
  推荐官：社交资本转化为金融资本，等级越高分润越高
  企业：零沉没成本，按效果付费
```

**核心转变**：
- 候选人：从"被推荐的对象" → "信任协议的数据资产所有者"（默认隐身，授权解锁）
- 推荐官：从"撮合交易的中间商" → "基于 TrustScore 提供专业服务的信任节点"（社交资本转化为金融资本）
- 企业：从"发布 JD 的需求方" → "信任协议的付费节点"（零沉没成本，按效果付费）

## 二、用户角色与痛点分析

### 2.1 五大核心用户角色 🆕（新增"候选人"角色）

#### 角色A：候选人（平台核心资产所有者）🆕

> **定义**：候选人是指在平台上拥有链上职业信用档案的求职者。每个候选人都是自己职业信用资产（CCA）的唯一所有者和授权管理者。

**画像**：
- 中高端人才（年薪 20 万以上），在职或观望机会
- 对自己的职业品牌有认知，希望被更精准地发现
- 有过被猎头/推荐者骚扰的经历，希望有更好的求职体验
- 对数据隐私敏感，不希望简历被随意倒卖

**核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 简历被平台倒卖/骚扰电话多 | ★★★★★ | 无法控制 | 自己掌控数据授权 |
| 面试反馈不透明 | ★★★★★ | 靠 HR 心情 | 不可篡改的面试记录 |
| 薪资历史不被认可 | ★★★★☆ | 每家公司都要重新证明 | 链上薪资记录可验证 |
| 每次求职都要重复描述经历 | ★★★★☆ | 靠记忆/简历 | 链上持续积累的能力标签 |
| 不知道自己值多少钱 | ★★★★☆ | 靠打听/面试试错 | 基于真实数据的信用评分 |

**候选人链上信用档案（CCA）包含内容（3D 简历体系）🆕**：

```
3D 简历 = 硬履历（1D） + 熟人背调（2D） + 推荐官信用分（3D）

候选人链上信用档案（Candidate Credit Asset）
│
├── 【1D·硬履历层】（JD 匹配，不可篡改的链上记录）
│   ├── 学历认证（链上哈希，可验证真实性）
│   ├── 工作经历时间线（经企业背书）
│   ├── 薪资历史（候选人授权脱敏上链）
│   └── 面试历史记录（企业面试结果，含评分和反馈）
│
├── 【2D·熟人背调层】（候选人主动授权解锁）
│   ├── 熟人对候选人的真实背书评价
│   ├── 前置背调记录（推荐前，推荐官填写熟人评价）
│   └── 背书人的信用分（背书人的 TrustScore 背书资质）
│
├── 【3D·信用评估层】（综合信用评分，动态更新）
│   ├── 综合信用评分（0-100，多维度计算）
│   ├── 推荐成功率（推荐入职数 / 被推荐总数）
│   ├── 能力标签（AI 解析 + 企业验证）
│   └── 薪资竞争力指数
│
└── 【价值流通层】（可变现的信用资产）
    ├── 优先推荐权（高信用候选人优先推送给推荐官）
    ├── 猎头让利资格（高信用候选人可要求推荐官降低费率）
    └── 数据收益权（候选人可从数据查询中获得 Token 收益）
```

#### 角色B：SOHO 推荐者（主力用户）

与 v1.2 保持一致，并新增：**链上声誉系统**——推荐者的每一次成功推荐、候选人评价都将上链，成为可携带的数字声誉资产。

#### 角色C：推荐人（行业专家）

与 v1.2 保持一致，并新增：**奖励 Token 链上发放**——推荐奖励以链上 Token 形式发放，可追溯、可携带，跨平台有效。

#### 角色D：企业 HR

与 v1.2 保持一致，并新增：**基于链上信用评估候选人**——企业可查看候选人完整的链上信用档案（经候选人授权），降低背调成本。

#### 角色E：小型推荐者公司

与 v1.2 保持一致。

### 2.2 用户旅程地图

#### 候选人的用户旅程（v1.3 新增核心旅程）🆕

```
【阶段一：入驻与信用初始化】
────────────────────
听说人人猎（推荐者/朋友推荐）→ 注册账号
→ 完成简历填写（基础信息 + 职业经历）
→ 选择数据授权范围（可设置公开/仅推荐者可见/仅企业可见）
→ 签署数据上链协议（候选人拥有数据所有权）
→ 获得初始信用评分（基于简历完整度和历史记录）
→ 链上身份生成（候选人持有私钥，拥有自己的 CCA）

【阶段二：信用积累与升值】
────────────────────
被推荐 → 参加面试 → 面试结果上链存证（企业确认）
→ 面试反馈上链（评分 + 简短评价）
→ 薪资谈判 → 入职确认 → 薪资记录上链（候选人授权脱敏）
→ 推荐者获得链上声誉加分
→ 候选人信用评分更新（动态升值）

【阶段三：信用资产变现】
────────────────────
信用评分达到目标阈值 → 解锁"优先推荐权"
→ 高信用候选人被推荐者优先搜寻
→ 享受"低费率推荐"权益（推荐者主动降低费率以获得候选人信任）
→ 高信用候选人可发起"反猎"（主动邀请猎头/推荐者来推荐自己）

【阶段四：信用资产传承】
────────────────────
换工作时 → 新企业背书历史自动携带
→ 不再需要重复证明自己的能力
→ 链上职业时间线持续生长
→ 信用评分随着职业发展持续升值
→ 候选人可选择将部分数据开放给行业薪资数据库（获得 Token 收益）
```

#### 推荐者的用户旅程（升级为链上声誉）🆕

```
【阶段一：入驻与链上声誉初始化】
────────────────────
注册账号 → 完成实名认证
→ 签署链上服务协议（推荐者的服务记录将上链存证）
→ 链上身份生成（推荐者持有私钥，拥有自己的声誉资产）
→ 初始声誉评分（基于平台认证 + 历史数据导入）

【阶段二：链上声誉积累】
────────────────────
接单 → 推荐候选人 → 候选人面试 → 面试结果上链
→ 成单 → 候选人确认 → 成单记录上链（不可篡改）
→ 候选人获得链上评价（好评/中评）
→ 推荐者链上声誉评分更新
→ 推荐者等级提升 → 享受更高权益

【阶段三：链上声誉变现】
────────────────────
链上声誉达到高等级 → 解锁"金牌推荐者"标识
→ 获得更多企业委托（企业更愿意选择有链上记录的推荐者）
→ 享受更高佣金比例
→ 链上声誉可在其他平台携带使用
→ 推荐者可在链上建立个人品牌（个人主页 = 链上声誉主页）
```

## 四、核心功能详细设计

### 4.1 【候选人链上信用档案（CCA）】—— 核心创新 🆕

> **核心理念**：每个候选人都应该拥有自己的职业信用资产，这份资产不可篡改、可携带、可持续升值。

#### 4.1.1 候选人链上信用档案的价值主张

**候选人的收益**：
- **数据所有权**：候选人拥有自己的简历数据，可自主决定谁可以查看
- **不可篡改的能力证明**：每一次面试、每一段工作经历、每一个能力标签，都经过企业背书上链，无法造假
- **持续升值的职业资产**：职业信用随时间积累，越资深越值钱
- **薪资历史可验证**：无需每次都重新证明自己的薪资水平

**推荐者的收益**：
- **候选人真实性有保障**：链上信用档案让简历信息更可信，减少面试翻车率
- **差异化竞争力**：推荐拥有链上信用档案的候选人，成功率更高

**企业的收益**：
- **背调成本降低**：链上历史记录减少重复背调工作
- **候选人质量更透明**：信用评分提供量化的候选人质量参考

#### 4.1.2 链上信用评分体系 🆕

**评分维度（100 分制）**：

| 维度 | 权重 | 说明 | 数据来源 |
|------|------|------|---------|
| **面试验证记录** | 30% | 经企业确认的面试历史，含通过/拒绝/评分 | 面试结果上链 |
| **推荐成功率** | 25% | 推荐入职数 / 被推荐总数（越高越好） | 链上成单记录 |
| **职业稳定性** | 20% | 平均在职时长、跳槽频率（稳定加分） | 链上工作经历 |
| **薪资竞争力** | 15% | 薪资在同级别市场中的分位数 | 链上薪资记录 |
| **能力标签丰富度** | 10% | 经验证的能力标签数量（越多越精准） | 企业背书标签 |

**评分等级**：

| 等级 | 评分 | 权益 | 标识 |
|------|------|------|------|
| ⭐ 职场新人 | 0-30 | 基础功能 | 🆕 新手上链 |
| ⭐⭐ 活跃候选人 | 31-55 | 平台基础服务 | 已验证 |
| ⭐⭐⭐ 资深候选人 | 56-75 | 优先推荐 | ⭐⭐⭐ 链上认证 |
| ⭐⭐⭐⭐ 行业专家 | 76-90 | 低费率推荐权益 + 企业主动邀请 | ⭐⭐⭐⭐ 行业认可 |
| ⭐⭐⭐⭐⭐ 顶尖人才 | 91-100 | 猎头反向竞争推荐权 + 专属服务 | 🏆 顶尖认证 |

## 五、OneID + 链上身份（DID）统一账号体系

### 5.1 账号类型与链上身份

| 账号类型 | 用户 | 链上身份（DID） | 核心资产 |
|---------|------|----------------|---------|
| 候选人 | 求职者 | ✅ 持有 DID（私钥） | Candidate Credit Asset (CCA) |
| 推荐者 | SOHO 推荐者 | ✅ 持有 DID | 链上声誉档案 + Token 钱包 |
| 推荐人 | 行业专家 | ✅ 持有 DID | 链上声誉 + Token 钱包 |
| 企业 HR | 企业招聘负责人 | ✅ 企业 DID（多签） | 企业背书记录 + 链上招聘数据 |
| 候选人（无链） | 基础用户 | ❌ 不上链 | 平台内信用记录 |

### 5.2 候选人链上入驻流程 🆕

```
注册账号 → 填写简历信息
  → 签署链上数据协议（候选人拥有数据所有权，可随时撤回）
  → 生成链上 DID（候选人持有私钥，平台不保存）
  → 简历数据加密存储（仅候选人授权可见）
  → 获得初始信用评分
  → 完成认证（如学历认证）→ 获得初始链上标签
  → 候选人入驻完成 → 开始积累 CCA
```

### 5.3 链上身份的核心保障 🆕

**私钥管理**：
- 候选人通过 Web3 钱包（如 MetaMask / 钱包 App）管理私钥
- 平台不保存私钥，无法代表候选人操作链上数据
- 候选人可随时导出/迁移自己的链上档案

**数据主权**：
- 候选人可随时撤回授权，删除平台内的数据
- 撤回后，平台将删除该候选人的所有数据（除已上链的必要记录）
- 已上链记录不可删除（区块链特性），但候选人可选择隐藏显示

## 六、底层算法与综合匹配度（信任协议引擎）🆕
> **核心公式（来自 PPT 0421）**：

```
综合匹配度 = [JD 契合度] × [圈层相似度 25%] × [推荐官 TrustScore 35%] × [关系权重]
```

**公式解读**：
- **JD 契合度**：候选人技能 / 经历与职位要求的匹配（1D 硬履历）
- **圈层相似度 25%**：候选人所在圈层（大厂圈 / 校友圈 / 行业圈）与目标企业的重叠度（2D 熟人背调）
- **推荐官 TrustScore 35%**：推荐官的信用背书质量（3D 信用层）
- **关系权重**：熟人人脉路径的强弱（一度 / 二度 / 三度连接）

**匹配流程**：
```
1️⃣ JD 解析 → 提取核心技能标签（AI）
2️⃣ 圈层相似度计算 → 找出候选人的大厂圈 / 校友圈重叠（区块链）
3️⃣ TrustScore 加权 → 推荐官的背书资质（智能合约）
4️⃣ 关系路径最短匹配 → 推荐官 → 候选人 → 企业（最短路径优先）
5️⃣ 综合得分排序 → 智能派 / 抢单（80% 智能 + 20% 抢单）
```

**防作弊机制**：
- 推荐官身份验证（Lv2+ 强信用节点）
- 底层隐私阀门（候选人控制授权）
- 劣质节点自动降权封号

## 九、竞争壁垒：三大不可迁移护城河 🆕

> **核心理念（来自 PPT 0421）**：对手可复制产品，但无法克隆信任网络。

| 护城河 | 具体内容 | 竞争对手难以复制的原因 |
|--------|---------|------------------|
| **独家三维数据资产** | 1D 硬履历（链上可验证）+ 2D 熟人背调 + 3D TrustScore | 整合熟人背调与 HR 真实履约评价，数据需要时间积累 |
| **沉睡高端隐私人才池** | 默认隐身 + 单向阀门，锁定全网最抗拒公开简历的顶尖被动人才 | 采用最严苛的"单次授权"设计，需要用户信任背书 |
| **不可迁移网状信用网络** | TrustScore 是推荐官沉淀的信用，不可带走 | 信任网络具有网络效应，越积累越难复制 |

**降维打击效应**：
- 对手可复制产品（功能、设计）
- 无法克隆信任网络（需要多年用户积累）
- 无法激活沉睡的顶级被动人才（需要隐私机制建立信任）

**链上存储策略**：
- 大文件（简历全文）：IPFS + 链上哈希存证
- 小数据（评分、标签、时间戳）：直接上链
- 隐私数据（薪资、联系方式）：zkProof 零知识证明，不暴露原文

### 11.2 关键假设与风险 🆕

| 假设/风险 | 说明 | 对策 |
|---------|------|------|
| **假设 1：候选人愿意建立链上档案** | 需要教育成本，候选人可能不信任 | 早期提供强力激励（Token 奖励），展示数据价值 |
| **假设 2：企业愿意确认面试结果上链** | 企业担心留下"被拒绝候选人的评价"的法律风险 | 提供匿名评价选项，仅显示分数不上传文字 |
| **假设 3：Token 价格稳定** | Token 波动可能影响推荐者激励效果 | 设置 $RRD→法币的自动兑换功能，降低波动风险 |
| **假设 4：链上声誉比平台内评分更有价值** | 用户可能不关心链上 vs 平台内 | 强调"跨平台携带"和"可验证不可篡改"的核心差异 |
| **风险 1：候选人链上数据泄露** | 候选人隐私数据（薪资等）上链后被破解 | 使用 zkProof 零知识证明，数据不暴露原文 |
| **风险 2：合规风险（Web3 + 招聘）** | 区块链 + 招聘在某些地区可能有监管不确定性 | 合规优先，功能按地区逐步开放 |
| **风险 3：推荐者/候选人绕开平台** | 链上记录可能让绕开平台更容易 | 通过 Token 经济绑定（质押 + 权益）增加绕开成本 |
| **风险 4：Web3 门槛过高** | 普通候选人可能不会使用钱包 | 提供"懒人模式"——平台托管私钥，降低使用门槛 |

## 十二、合规与隐私设计 🆕

### 12.1 数据合规框架

| 法规 | 合规措施 |
|------|---------|
| **个保法（2021）** | 候选人明确授权后上链；链上数据最小化（不上传完整身份证号） |
| **GDPR（欧盟候选人）** | 提供"被遗忘权"——候选人可撤回授权，平台删除数据（链上记录除外，需说明） |
| **区块链特性** | 链上记录不可删除，需提前告知候选人；提供"隐藏"功能而非"删除" |
| **招聘合规** | 企业不得基于链上信用档案进行歧视性招聘（平台条款约束） |

### 12.2 候选人数据授权层级

```
Level 0：完全私密
  └── 数据仅本地存储，不上链，不给任何人看

Level 1：平台内可见
  └── 简历可见，但不上链，无法被推荐者/企业直接查看链上档案

Level 2：推荐者可见（需候选人确认）
  └── 推荐者可申请查看候选人档案，候选人审批后可查看

Level 3：企业可见（需候选人主动授权）
  └── 企业可查看候选人链上信用档案，候选人主动申请推荐时授权

Level 4：公开（需候选人主动开启）
  └── 公开候选人信用评分区间（不暴露具体数据），用于"被动求职"
```

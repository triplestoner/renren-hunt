# PRD v1.7 修复补丁：角色C和角色D详细画像

## 角色C：推荐人（行业专家）

| 维度 | 说明 |
|------|------|
| **定义** | 不以猎头服务为主要职业，但在特定行业有深厚人脉和专业知识，愿意向朋友推荐职位的行业从业者（如企业高管、技术专家、行业顾问） |
| **画像** | 某行业5年以上从业经验，有稳定的职业圈层人脉；对行业人才流动有洞察，愿意帮助朋友对接机会；不以推荐为主要收入来源，但希望获得推荐奖励认可 |
| **核心诉求** | 获得推荐奖励（RRP积分）、建立职业圈层影响力、帮助朋友找到好机会、降低推荐流程复杂度 |
| **链上资产** | 推荐人链上声誉档案（推荐成功次数）+ RRP钱包 |
| **差异于SOHO猎头** | 推荐为兼职/偶发行为，不是全职猎头；不需要猎头认证体系；主要依赖自有圈层，不是主动搜寻候选人 |

**推荐人核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 推荐奖励不透明/拖欠 | ★★★★☆ | 朋友口头感谢，无实质奖励 | 平台自动计算并发放RRP奖励 |
| 推荐进度不可追踪 | ★★★★☆ | 朋友转告，信息滞后 | 实时推送推荐状态变更 |
| 推荐关系无存证 | ★★★☆☆ | 无法证明"是我推荐的" | 链上存证推荐关系，不可篡改 |
| 不确定朋友是否适合 | ★★★☆☆ | 凭经验判断 | AI匹配度预测辅助判断 |

## 角色D：企业HR（需求方）

| 维度 | 说明 |
|------|------|
| **定义** | 在平台上发布猎头委托、管理候选人推荐流程的企业招聘负责人 |
| **画像** | 大中型企业HRBP或招聘负责人，有猎头预算但希望降低成本；对猎头推荐质量有要求，但传统猎头交付不稳定；希望精准触达被动人才，但缺乏直接触达渠道 |
| **核心诉求** | 降低猎头费用（从20-30%降至15-20%）、精准触达被动人才、面试结果可追溯、候选人质量有保障 |
| **链上资产** | 企业链上认证档案 + 链上候选人评价记录 + 智能合约托管账户 |
| **核心痛点** | 见下方表格 |

**企业HR核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 猎头费用过高（年薪20-30%） | ★★★★★ | 无替代方案，被动接受 | 平台费率降至15-20%，节省成本 |
| 推荐质量不稳定 | ★★★★★ | 靠猎头口碑选择，但难以量化 | TrustScore体系筛选高质量猎头 |
| 无法触达被动人才 | ★★★★☆ | 依赖猎头私域，效率低 | 候选人默认隐身+授权解锁机制 |
| 面试反馈无存证 | ★★★☆☆ | 内部记录，无法复用 | 面试结果链上存证，可追溯 |
| 猎头飞单/简历泄露 | ★★★☆☆ | 无法防范 | 推荐关系链上存证，可追溯 |

## 用户旅程补充

### 推荐人用户旅程（链上版本）

```
【阶段一：入驻与发现】
────────────────────
注册账号（无需猎头认证）→ 浏览优质职位HC
→ 平台推送匹配其行业的岗位（基于其职业标签）
→ 发现适合推荐给朋友的职位

【阶段二：推荐与分享】
────────────────────
选择职位 → 一键生成分享链接（含推荐人ID）
→ 通过微信/脉脉/朋友圈分享给候选人
→ 候选人通过链接注册 → 自动绑定推荐关系上链

【阶段三：追踪与反馈】
────────────────────
查看推荐状态（已查看/已申请/面试中/已录用）
→ 收到实时推送通知
→ 了解候选人的面试进度（候选人授权后可见）

【阶段四：奖励发放】
────────────────────
候选人成功入职 → 过保证期（90天）
→ 平台自动计算奖励（推荐服务费的10-15%）
→ 奖励发放至RRP钱包（链上积分）
→ 推荐人排名提升 → 解锁更多优质职位推送

【阶段五：持续推荐】
────────────────────
查看推荐历史 → 分析哪些职位更容易成功
→ 获得平台推荐优化建议
→ 成为高信任推荐人 → 解锁专属高薪职位
```

### 企业HR用户旅程（链上版本）

```
【阶段一：入驻与认证】
────────────────────
注册账号 → 完成企业认证（营业执照/授权书）
→ 绑定链上企业身份（DID）
→ 设置猎头费率偏好（15-20%）
→ 预付托管账户开通（持牌支付机构托管）

【阶段二：发布委托】
────────────────────
填写JD需求 → JD解析AI生成关键词标签
→ 设置圈层偏好（腾讯/字节/阿里等）
→ 设置TrustScore门槛（如≥60分）
→ 设置保证期（默认90天）
→ 发布至猎头工作台 → 链上存证发布记录

【阶段三：候选人管理】
────────────────────
猎头推荐候选人 → 查看候选人链上信用档案（授权后）
→ 查看推荐官TrustScore → 决定是否接受推荐
→ 安排面试 → 面试结果上链存证（评分+反馈）

【阶段四：入职确认】
────────────────────
候选人入职 → 企业确认入职（触发入职确认合约）
→ 保证期开始追踪 → 90天后自动触发分账
→ 智能合约自动分账（猎头70%/候选人15%/平台15%）
→ HR强制评价（能力匹配度/猎头跟进质量/专业度）

【阶段五：持续合作】
────────────────────
查看猎头链上声誉档案 → 筛选高质量猎头优先合作
→ 建立长期合作关系 → 猎头圈层资源沉淀
→ 发布定向发榜（指定高TrustScore猎头）
```

## 补充说明

### 职业时间线与隐身机制的兼容性

**原则**：职业时间线为候选人私有，仅在候选人主动授权或猎头推荐时解锁给特定对象查看。

**具体机制**：
- 候选人默认隐身：职业时间线对外不可见
- 猎头推荐时：候选人可选择性授权解锁部分时间线给猎头查看
- 企业面试时：候选人可授权解锁时间线给HR查看（用于面试评估）
- 入职后：企业背书自动添加到时间线，但需候选人确认后才上链

**收益权**：候选人可选择将部分脱敏数据开放给行业薪资数据库，获得RRP收益。

### 圈层数据来源说明

**数据获取方式**：

1. **候选人授权导入**：
   - 候选人微信/脉脉授权导入好友关系
   - 系统自动识别好友的职业标签（基于公开资料）
   - 计算圈层覆盖度

2. **猎头填写前置背调**：
   - 猎头推荐前填写候选人熟人背调
   - 标注候选人的圈层标签（如"腾讯离职"、"字节圈层"）
   - 系统验证猎头的圈层可信度

3. **企业背书验证**：
   - 候选人入职后，企业背书自动添加工作经历
   - 验证候选人声称的圈层真实性

**隐私保护**：
- 社交图谱数据不上链，仅链下加密存储
- 圈层标签仅用于匹配计算，不公开显示具体人脉关系
- 候选人可随时撤销授权

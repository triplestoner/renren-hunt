## 一、产品愿景与战略定位

### 1.1 产品愿景
**打造全球首个基于区块链的猎头信用体系，让招聘回归信任本质。**

通过链上存证 + 信用评分 + 智能合约分账，解决传统猎头行业的信任危机，让：
- **候选人**掌握职业数据主权，告别简历造假
- **猎头**建立不可篡改的职业声誉，降低获客成本
- **企业**降低猎头费用（从20-30%降至15-20%），提升招聘质量
- **推荐人**获得透明奖励，参与信任生态建设

### 1.2 核心问题（痛点）
| 角色 | 核心痛点 | 当前解决方案 | 我们的方案 |
|------|---------|------------|-----------|
| 候选人 | 简历造假泛滥，职业信用无法积累 | 无有效方案 | 链上CCA信用档案 + 企业背书 |
| 猎头 | 信任无法证明，获客成本高 | 口口相传，无量化指标 | 链上TrustScore + 推荐成功率存证 |
| 企业HR | 猎头费用高（20-30%），质量不稳定 | 依赖猎头公司口碑 | TrustScore筛选 + 智能合约托管分账 |
| 推荐人 | 推荐奖励不透明，进度不可追踪 | 朋友口头感谢 | RRP积分自动发放 + 链上推荐关系存证 |

### 1.3 产品定位
**人人猎 = 链上猎头信用基础设施 + AI匹配引擎 + 智能合约分账系统**

- **不是**传统猎头公司（我们不雇猎头）
- **不是**简单招聘平台（我们有链上信用体系）
- **是**猎头行业的信任基础设施（提供TrustScore、CCA、RRP结算）

### 1.4 核心价值主张
1. **信任可量化**：TrustScore基于链上数据，不可篡改，可跨平台迁移
2. **数据主权回归**：候选人拥有职业数据私钥，授权使用，随时撤销
3. **分账自动化**：智能合约自动分账（猎头70%/候选人15%/平台15%），90天保证期
4. **匹配智能化**：综合匹配度算法（JD契合度+圈层相似度+TrustScore+关系权重）

## 二、用户角色与痛点分析

### 2.1 五大核心用户角色

#### 角色A：候选人（核心用户）
| 维度 | 说明 |
|------|------|
| **定义** | 被动或主动寻找新机会的职场人士，是平台最核心的资产持有者 |
| **画像** | 25-40岁，本科以上学历，年薪20-200万；在一线/新一线城市工作3年以上；对职业隐私敏感，不愿公开简历；希望通过熟人推荐获得更好机会 |
| **核心诉求** | 保护职业隐私（隐身模式）、获得公平推荐机会、建立不可篡改的职业信用、通过推荐获得RRP奖励 |
| **链上资产** | CCA（候选人信用档案）+ OneID + RRP钱包 |

**候选人核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 简历造假泛滥，职业信用无法积累 | ★★★★★ | 无有效方案 | 链上CCA信用档案 + 企业背书 |
| 简历被滥投，隐私泄露风险高 | ★★★★★ | 投简历后无法控制流向 | 隐身模式 + 授权解锁机制 |
| 无法证明自己的能力，只能靠"包装" | ★★★★☆ | 无量化能力证明 | 企业背书 + 项目成果上链 |
| 猎头推荐质量参差不齐 | ★★★★☆ | 只能靠运气 | 查看猎头TrustScore + 推荐历史 |
| 面试反馈不透明，不知为何被拒 | ★★★☆☆ | 通常无反馈 | 面试结果链上存证（评分+评价） |

#### 角色B：SOHO猎头（自由职业猎头）
| 维度 | 说明 |
|------|------|
| **定义** | 独立工作的自由职业猎头，不隶属于大型猎头公司，依赖个人圈层完成推荐 |
| **画像** | 30-45岁，5年以上猎头经验，积累了稳定的候选人圈层；厌倦了传统猎头公司的分成模式（通常只能拿20-30%）；希望通过平台建立个人品牌和信用 |
| **核心诉求** | 建立链上TrustScore信用档案、降低获客成本、获得更高分成比例（平台仅抽15%）、通过高质量推荐提升排名 |
| **链上资产** | TrustScore档案 + 推荐历史存证 + RRP钱包 |

**SOHO猎头核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 信用无法证明，每次都要重新建立信任 | ★★★★★ | 口口相传，无量化指标 | 链上TrustScore + 推荐成功率存证 |
| 传统猎头公司抽成高（50-70%） | ★★★★★ | 只能接受低分成 | 平台仅抽15%，智能合约自动分账 |
| 候选人圈层有限，难以触达被动人才 | ★★★★☆ | 依赖个人人脉 | 平台AI匹配 + 候选人授权解锁 |
| 推荐进度不透明，成单周期长 | ★★★★☆ | 靠电话/微信追问 | 链上实时追踪推荐状态 |
| 简历造假难以识别 | ★★★☆☆ | 背景调查成本高 | 候选人CCA信用档案自动验证 |

#### 角色C：推荐人（行业专家）

| 维度 | 说明 |
|------|------|
| **定义** | 不以猎头服务为主要职业，但在特定行业有深厚人脉和专业知识，愿意向朋友推荐职位的行业从业者（如企业高管、技术专家、行业顾问） |
| **画像** | 某行业5年以上从业经验，有稳定的职业圈层人脉；对行业人才流动有洞察，愿意帮助朋友对接机会；不以推荐为主要收入来源，但希望获得推荐奖励认可 |
| **核心诉求** | 获得推荐奖励（RRP积分）、建立职业圈层影响力、帮助朋友找到好机会、降低推荐流程复杂度 |
| **链上资产** | 推荐人链上声誉档案（推荐成功次数）+ RRP钱包 |
| **差异于SOHO猎头** | 推荐为兼职/偶发行为，不是全职猎头；不需要猎头认证体系；主要依赖自有圈层，不是主动搜寻候选人 |

**推荐人核心痛点**：

| 痛点 | 严重程度 | 当前解决方案 | 期望方案 |
|-----|---------|------------|---------|
| 推荐奖励不透明/拖欠 | ★★★★☆ | 朋友口头感谢，无实质奖励 | 平台自动计算并发放RRP奖励 |
| 推荐进度不可追踪 | ★★★★☆ | 朋友转告，信息滞后 | 实时推送推荐状态变更 |
| 推荐关系无存证 | ★★★☆☆ | 无法证明"是我推荐的" | 链上存证推荐关系，不可篡改 |
| 不确定朋友是否适合 | ★★★☆☆ | 凭经验判断 | AI匹配度预测辅助判断 |

### 2.2 用户旅程地图

#### 候选人用户旅程（链上版本）

```
【阶段一：入驻与身份初始化】
────────────────────
注册账号 → 完成实名认证（KYC）
→ 生成OneID（链上身份DID）
→ 填写简历（硬履历+项目经验）
→ 设置隐身模式（默认对猎头不可见）
→ 获得初始CCA信用档案（空）

【阶段二：信用积累与授权】
────────────────────
完善简历 → 邀请前雇主/同事背书（链上存证）
→ 上传项目成果（GitHub/作品集）
→ 设置授权范围（哪些猎头/企业可查看）
→ 职业时间线自动生成（工作经历上链）

【阶段三：被动推荐与匹配】
────────────────────
猎头发现候选人（通过圈层推荐/AI匹配）
→ 候选人收到授权请求（猎头想查看简历）
→ 查看猎头TrustScore + 推荐历史
→ 决定是否授权解锁简历

【阶段四：面试与反馈】
────────────────────
接受面试邀请 → 查看企业信息（链上认证）
→ 完成面试 → 查看面试反馈（链上存证）
→ 拒绝/接受Offer → 入职确认

【阶段五：信用升值与收益】
────────────────────
成功入职 → 企业背书自动添加到CCA
→ TrustScore提升 → RRP奖励到账（入职奖金）
→ 职业信用升值 → 更多优质机会主动找上门
→ 推荐朋友入职 → 获得推荐奖励RRP
```

### 3.3 六步流转商业飞轮（从v1.4补入）

## 四、核心功能详细设计

### 4.1 TrustScore算法详细设计

#### 4.1.1 数据来源与输入

**数据输入1:猎头身份认证**
├── 实名认证(手机号 + 身份证 + 活体检测)→ 防止一人多号
├── 从业资质认证(猎头从业资格证/公司营业执照)→ 职业身份确认
└── 社交账号绑定(微信/LinkedIn)→ 增加账号真实性

**数据输入2:圈层数据**
├── 候选人社交图谱分析(微信/脉脉好友关系导入)
├── 行业圈层标签(腾讯系/字节系/阿里系/外企系等)
└── 职业社交影响力(脉脉影响力指数/行业知名度)

**数据获取方式**：
1. 候选人微信/脉脉授权导入好友关系
2. 猎头填写前置背调时标注候选人圈层标签
3. 企业背书验证候选人工作经历真实性

**隐私保护**：社交图谱数据不上链，仅链下加密存储

**数据输入3:推荐历史存证**
├── 链上记录：推荐ID、猎头ID、候选人ID、职位ID、时间戳
├── 推荐结果：面试/录用/入职/失败
└── 企业反馈：评分(1-5星) + 文字评价

**数据输入4:成单率与质量**
├── 成单率 = 入职数 / 推荐总数
├── 平均薪资涨幅 = ∑(新薪资 - 原薪资) / 入职数
└── 保证期通过率 = 90天内未离职数 / 入职数

**数据输入5:CCA信用数据**（候选人授权后）
├── 候选人职业时间线(工作经历上链)
├── 企业背书记载(前雇主评价)
└── 候选人隐身授权记录(授权猎头查看的次数与范围)

---

**职业时间线与隐身机制兼容性**：
- 职业时间线为候选人私有，默认隐身
- 仅在候选人主动授权或猎头推荐时解锁给特定对象查看
- 企业背书自动添加到时间线，但需候选人确认后才上链

#### 4.1.2 TrustScore计算公式（v1.4增强版）

```
TrustScore = 基础分(50) + 成单加分(30) + 评价加分(15) + 信用加分(5) - 违规扣分(不封顶)

其中：
1. 基础分(50分)：完成实名认证+从业资质认证 → 自动获得
2. 成单加分(最高30分)：
   - 每成功入职1人 → +3分（最高30分）
   - 保证期通过率≥90% → 额外+5分
   - 平均薪资涨幅≥30% → 额外+5分
3. 评价加分(最高15分)：
   - 企业HR评价：每次面试反馈 +0.5分（最高10分）
   - 候选人评价：每次授权解锁 +0.2分（最高5分）
4. 信用加分(最高5分)：
   - 连续90天无违规 → +2分
   - 推荐信息真实无造假 → +3分（基于CCA验证）
5. 违规扣分(不封顶)：
   - 简历造假 → -20分/次
   - 候选人投诉属实 → -10分/次
   - 推荐后失联 → -5分/次
```

**TrustScore等级划分**：
| 分数段 | 等级 | 称号 | 权益 |
|--------|------|------|------|
| 80-100 | S级 | 金牌猎头 | 优先接高薪HC、平台流量倾斜、分账比例可协商 |
| 60-79  | A级 | 优质猎头 | 正常推荐权限、RRP奖励系数1.0 |
| 40-59  | B级 | 新人猎头 | 限制每日推荐次数（≤5次）、需导师审核 |
| 20-39  | C级 | 观察期猎头 | 仅能推荐低薪岗位、推荐需人工审核 |
| <20    | D级 | 黑名单 | 禁止推荐、需重新认证 |

#### 4.1.3 动态更新机制

- **实时更新**：成单、评价、投诉等事件触发即时更新
- **每日快照**：每天凌晨2点重新计算所有猎头TrustScore
- **链上存证**：每次更新均记录到区块链（不可篡改）
- **公示期**：扣分操作需公示7天，猎头可申诉

/**
 * @title RRPRegistry - RRP积分注册合约
 * @dev 管理RRP积分的铸造、转账、消耗
 */
contract RRPRegistry {
    string public name = "RenrenLie Point";
    string public symbol = "RRP";
    uint8 public decimals = 18;
    uint256 public totalSupply;
    
    mapping(address => uint256) public balanceOf;
    mapping(address => mapping(address => uint256)) public allowance;
    
    event Transfer(address indexed from, address indexed to, uint256 value);
    event Approval(address indexed owner, address indexed spender, uint256 value);
    
    address public admin;
    mapping(address => bool) public authorizedContracts;
    
    modifier onlyAdmin() {
        require(msg.sender == admin, "Not admin");
        _;
    }
    
    modifier onlyAuthorized() {
        require(authorizedContracts[msg.sender], "Not authorized");
        _;
    }
    
    constructor() {
        admin = msg.sender;
        totalSupply = 100000000 * 10**decimals; // 1亿RRP初始发行
        balanceOf[admin] = totalSupply;
    }

        require(balanceOf[msg.sender] >= amount, "Insufficient balance");
        balanceOf[msg.sender] -= amount;
        balanceOf[to] += amount;
        emit Transfer(msg.sender, to, amount);
        return true;
    }
    
    function mint(address to, uint256 amount) external onlyAuthorized {
        totalSupply += amount;
        balanceOf[to] += amount;
        emit Transfer(address(0), to, amount);
    }

### 4.4 综合匹配度算法公式（从v1.4补入）

> **核心理念**：候选人与职位的匹配不是简单的关键词匹配，而是多维度的综合匹配度计算。

#### 公式定义

```
综合匹配度 = JD契合度 × 0.4 + 圈层相似度 × 0.25 + TrustScore权重 × 0.20 + 关系权重 × 0.15

取值范围：0-100分
推荐阈值：≥60分 → 系统自动推送给猎头
优质阈值：≥80分 → 系统优先推荐给高TrustScore猎头
```

#### 各维度详细计算

##### 1. JD契合度（权重40%）

**计算方式**：基于LLM语义理解，对比JD需求与候选人简历

```
JD契合度 = (技能匹配度 × 0.3 + 经验匹配度 × 0.3 + 薪资匹配度 × 0.2 + 行业匹配度 × 0.2)

其中：
- 技能匹配度：JD关键词与候选人能力标签的语义匹配（AI解析）
- 经验匹配度：JD年限要求与候选人工作年限对比
- 薪资匹配度：JD薪资范围与候选人期望薪资匹配度
- 行业匹配度：JD行业与候选人行业背景匹配度

取值范围：0-100分
```

##### 2. 圈层相似度（权重25%）

**计算方式**：基于社交图谱分析，计算候选人与目标企业圈层重叠度

```
圈层相似度 = Σ(圈层权重 × 圈层重叠度)

其中：
- 大厂圈层权重：1.0（腾讯/字节/阿里/美团/拼多多）
- 行业圈层权重：0.7（互联网/金融/医疗/教育）
- 校友圈层权重：0.5（985/211/海外名校）

圈层重叠度 = 候选人圈层与目标企业圈层重叠的人数 / 候选人总圈层人数

取值范围：0-100分
```

##### 3. TrustScore权重（权重20%）

**计算方式**：推荐猎头的TrustScore高低影响匹配可信度

```
TrustScore权重 = 推荐猎头TrustScore / 100

取值范围：0-100分（猎头TrustScore为0-100）

说明：高TrustScore猎头推荐的候选人，匹配可信度更高
```

##### 4. 关系权重（权重15%）

**计算方式**：推荐猎头与候选人的关系亲疏影响推荐可信度

```
关系权重 = 关系类型权重 × 关系强度

其中：
- 一度人脉（直接朋友）：权重 1.0
- 二度人脉（朋友的朋友）：权重 0.7
- 三度人脉（陌生人）：权重 0.3

关系强度 = 猎头对候选人的熟悉程度评分（1-5星）× 0.2

取值范围：0-100分
```

#### 匹配度应用场景

| 场景 | 应用方式 |
|------|----------|
| **猎头HC推荐** | 系统筛选匹配度≥60的候选人，推送给猎头 |
| **候选人职位推荐** | 系统筛选匹配度≥60的职位，推送给候选人 |
| **优先推荐** | 匹配度≥80的候选人，优先推送给高TrustScore猎头 |
| **匹配排序** | 按匹配度降序排列候选人列表，猎头从高匹配度开始推荐 |

| 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|---------|

|------|------|------|---------|
